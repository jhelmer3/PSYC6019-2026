The tidyverse

Let’s get ready to use some tidyverse code!

We must first install the tidyverse with the install.packages("packagename") function.

This will install all packages within the tidyverse, so we don’t have to install each manually.

You only have to install packages once per R download (and then whenever you want to update a package).

install.packages("tidyverse")

To load the tidyverse packages into the R environment, we use the library(package) function. You will have to run this line once per R session (i.e., every time you restart R).

Tidy: Principles

Three rules to a tidy dataset

  1. Each variable is a column; each column is a variable.

  2. Each observation is a row; each row is an observation.

  3. Each value is a cell; each cell is a single value.

https://r4ds.hadley.nz/data-tidy.html#fig-tidy-structure

Tidy: Why Tidy?

  1. Consistency! Any sort of consistency in your data management will be beneficial.
  1. R loves vectors! Having variables in columns plays well with many functions.
  1. Cohesion with an ecosystem of R packages that expect tidy data.

Transform: tidyverse syntax

The tidyverse website mentioned that each package shares a common language for their functions

Based off of dplyr (one of the packages) verbs

  1. The first argument is always a dataframe.

  2. The subsequent arguments typically describe which columns to operate on using the variable names (without quotes).

  3. The output is always a new data frame.

https://r4ds.hadley.nz/data-transform.html#dplyr-basics

Transform: More tidyverse syntax

One more thing…

tidyverse verbs work best in a pipe: |>

How we’ve been using functions:

output <- function(input)

Functions in a pipe:

output <- input |> function()

Why is this helpful?

Many functions together:

another_function(other_function(function(input)))

Functions in a pipe:

input |>
  function() |>
  other_function() |>
  another_function()

Back to the violin plot, we can layer on the observed data by adding a point plot with geom_point().

But, the points are all overlapping and hard to see at the different levels of position.

We can nudge them off their data value by using geom_jitter(). But, we only want it to nudge on the y-axis, not the x-axis.

So, we will need to set geom_jitter()’s width argument to 0. Otherwise, it’ll try to move the points on their minutes_played value, too.

  • Code
ggplot(data = player_stats,
       mapping = aes(x = minutes_played, y = position)) +
  geom_violin() + 
  geom_point()
